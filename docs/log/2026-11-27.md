## Learned / constraints

- An async reactor has overhead when only one request is in flight; the benchmark does not exercise
  concurrency, cancellation, partial writes or backpressure.
- The benchmark uses the same frame encoding and payload sizes as the blocking reference.
- WSL2 loopback is not a LAN or native-Linux measurement.
- No allocation, CPU-time or peak-memory measurements yet.

## Next actions

1. Add a 32–128 concurrent-client Asio benchmark and a comparable blocking reference.
2. Measure allocations, CPU time and peak memory.
3. Add LAN/native Windows/ARM64 runs when available.
4. Keep the `Stream` boundary and blocking reference until the concurrency data is clear.
5. Continue with Protobuf schemas and session replay/heartbeat.
