# 2026-11-26

## Goal

Start the next implementation step after the fabric session slice: benchmark the control-message
codecs and make the serializer decision.

## What changed

- Added `benchmarks/codec/` with equivalent `Submit` and `NodeDescriptor` schemas for Protocol
  Buffers, FlatBuffers and Cap'n Proto.
- Added a pinned FetchContent benchmark harness, a `wsl-codec-bench` preset and parameterless
  `scripts/bench-codec.ps1` / `scripts/bench-codec.cmd`.
- Ran the benchmark three times on WSL2 Ubuntu 24.04 with GCC 13.3 Release.
- Selected **Protocol Buffers** for V1 control payloads in [Q-47](../decisions/fabric-services.md#q-47).
- Resolved [OI-14](../questions/README.md#oi-14-serializer-selection) and updated the wire spec,
  cross-cutting tech table, fabric/versioning notes, decision map, open-question map and
  implementation map.
- Added [the codec benchmark report](../reports/005-codec-benchmark.md).

## Results

| Message/profile | Protobuf | FlatBuffers | Cap'n Proto |
|---|---:|---:|---:|
| Submit typical bytes | 1051 | 1728 | 1632 |
| Submit large bytes | 27865 | 32504 | 33048 |
| Submit typical decode p50 | 1.91 µs | 0.24 µs | 0.11 µs |
| Submit large decode p50 | 20.73 µs | 1.67 µs | 0.25 µs |

Protobuf is smaller and its latency remains far below the 1 ms control target. Cap'n Proto is the
latency leader; FlatBuffers is not best on either size or latency. Full tables and method are in the
report.

## Learned / constraints

- Fetching and building all three codecs is heavy; the benchmark is an opt-in target and should not
  be part of ordinary builds.
- Building third-party dependencies with the project C++23 standard is slow; the benchmark subproject
  uses C++17 for dependencies while the harness itself requests C++20.
- The benchmark currently covers two message shapes; heartbeat, service, error and artifact-location
  cases still need coverage.
- Allocations, memory peaks, schema evolution and native Windows/ARM64 are unmeasured.
- The branch is stacked on the unmerged transport and session branches.
