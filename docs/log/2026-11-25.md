# 2026-11-25

## Goal

Start implementation against the documented plan and add a second-brain layer to the docs.

## What changed

### Core model

- Added CMake project, presets, warning options and a dependency-free test harness.
- Implemented `pluribuscore`:
  - UUID-based strong IDs and SHA-256 artifact IDs;
  - portable error codes;
  - names, ABI versions, architectures and compatibility keys;
  - `ExecutableRef`, `ExecutionSpec`, resource/scheduling constraints;
  - sandbox-relative path validation;
  - execution state machine;
  - node and service descriptors.
- Added 22 core unit tests.

### Scheduler

- Implemented `pluribusscheduler` as a pure V1 function.
- Added exact 128/256-bit arithmetic for score comparison.
- Implemented static filtering, freshness, conservative reservations, projection score and
  deterministic tie-breaks.
- Added 16 scheduler tests, including the worked example and exact ties.

### Fabric

- Added `pluribusfabric` control framing:
  - network-byte-order length/version/type/flags/sequence header;
  - 1 MiB control-frame limit;
  - incremental, non-blocking decoder with error latching;
  - provisional bootstrap message type constants.
- Added 10 fabric tests, including arbitrary chunking and malformed frames.

### Documentation

- Added the second-brain layer:
  - home dashboard, knowledge-base guide, glossary and inbox;
  - maps for architecture, specs, implementation, decisions, open questions and knowledge;
  - 19 atomic concept notes;
  - 6 themed decision files containing 46 records, plus the ordered decision index;
  - 28 open-question register entries;
  - templates, references, archive policy and this log.
- Added frontmatter and knowledge-base links to the canonical architecture/spec documents.

### Follow-up

- Grouped the 46 per-question decision records into six thematic files: `scope`, `execution`,
  `control-plane`, `fabric-services`, `store-packaging` and `engineering`.
- Kept every `Q-N` ID as a section with a stable `#q-N` anchor.
- Updated the decision index, decision map, questions and notes to point at the themed sections.
- Created the `dev` integration branch and started the task-branch/report workflow.
- Added `AGENTS.md`, `docs/reports/`, a report template, parameterless `scripts/check-docs.ps1` /
  `scripts/check-docs.cmd` checks and the first task report.
- Merged `chore/task-workflow` into `dev` after review.

### Open question guidance

- Expanded all 28 open-question entries with an explanation, a suggested behavior, trade-offs,
  confidence and a next action.
- Added explicit “proposal, not decision” guidance and updated the question template, map and home
  page.
- Added [the task report](../reports/open-question-guidance.md) for review.
- Accepted the open-question guidance and merged `chore/open-question-guidance` into `dev`.

## Learned / constraints

- The existing decision table was a good source for ADR stubs, but rationale still lives in the
  canonical docs; records must be expanded when revisited.
- The serializer and control schema remain the largest blocker for a real fabric connection.
- The custom test harness works but is not the long-term vcpkg/GoogleTest baseline.
